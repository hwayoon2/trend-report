# 국내 스타트업 투자 주간 리포트

목표: 미국판(`vc-weekly-report`)과 **같은 구성, 같은 깊이**의 국내판 리포트. 디자인과 HTML은 `tools/build_report.py`가 고정으로 만든다.
너는 **조사하고 `data/kr/START.json`을 채우는 일**만 한다. HTML을 직접 쓰지 말 것.

견본: 첫 국내판이 생기기 전까지는 미국판 `data/2026-10-26.json`의 길이·톤·깊이를 기준으로 삼는다. 이후에는 가장 최근 `data/kr/*.json`을 열어 맞춘다.

## 0. 기간
`date -u` → 대상 주 = 지난주 월(START)~일(END). 파일명은 START.

## 1. 정보원 (우선순위)
| 정보원 | 무엇을 볼까 | 검색 방법 |
|---|---|---|
| **스타트업레시피** (startuprecipe.co.kr) | ① **주간 투자 리포트** (`wp-content/uploads/YYYY/MM/YYMMDD_weekly_startuprecipe_*.pdf`, 해당 주 투자 유치 기업 목록·건수·공개 총액). **우리 Top 10은 이 목록 기준** ② 개별 투자 기사 | WebSearch `allowed_domains:["startuprecipe.co.kr"]` + "주간 투자" + 날짜. PDF는 WebFetch로 열고, 안 되면 `curl -sL URL -o /tmp/w.pdf && pdftotext /tmp/w.pdf -` |
| **혁신의숲** (innoforest.co.kr) | ① "국내 스타트업 주간 투자동향" (스타트업레시피 PDF를 못 열 때 대체 목록) ② **월간 투자결산** (월 총액, 섹터 비중, 메가딜 수) | WebSearch `allowed_domains:["innoforest.co.kr"]` |
| **THE VC** (thevc.kr) | 기업별 투자 이력·투자사·누적 투자액 → 딜 카드의 `history` | WebSearch `allowed_domains:["thevc.kr"]` + 회사명 |
| **투자 기사** | 딜 카드의 1차 출처. 창업자 배경, 사업 내용, 투자사 코멘트, 자금 용도를 **기사 본문을 WebFetch로 열어 읽는다**. 검색 스니펫만으로 카드를 쓰지 말 것 | 플래텀(platum.kr), 벤처스퀘어(venturesquare.net), 유니콘팩토리(unicornfactory.co.kr), 아웃스탠딩, 매일경제·한국경제·머니투데이·더벨(일부 유료) |
| **통계** | 중소벤처기업부 벤처투자 동향(월·분기), 한국벤처캐피탈협회(KVCA) 통계 | WebSearch "벤처투자 동향" + 월 |
| **상장·정책** | 한국거래소 KIND(상장예비심사 청구·승인, 신규상장), 38커뮤니케이션(수요예측·공모 일정), 한국벤처투자(모태펀드 출자사업), 중기부 보도자료 | WebSearch |

- WebFetch가 막히면(ENOTFOUND/403) 검색 스니펫으로 재구성하고 `limits`에 **어떤 정보원이 막혔는지** 적는다.
- **다른 주 회차와 혼동 금지**: 리포트의 대상 기간이 START~END인지 확인해 `source.note`에 "발행일, 집계 기간"을 적는다. 해당 주 회차가 아직 없으면 혁신의숲 주간 투자동향 → 기사 검색 순으로 목록을 복원하고 `rank_estimated: true`.

## 2. Top 10 선정 규칙
- **Top 10 = 해당 주 스타트업레시피 목록 중 금액 공개 딜을 금액 순으로 상위 10개.** 같은 금액이면 공동 순위.
- 금액 비공개 딜은 Top 10에 넣지 않는다. 비공개라도 큰 딜(유명 VC 리드, 시리즈 C 이상 등)이나 해외 VC의 국내 투자는 `others`에 넣는다.
- 목록 밖 딜을 찾아 Top 10에 끼워 넣거나 재정렬하지 않는다.
- 금액이 "OO억원 이상"·"약 OO억원"이면 그 숫자를 쓰고 `round`나 `funding`에 표시한다. 누적 금액(예: "누적 500억원")과 이번 라운드 금액을 혼동하지 말 것.

## 3. 딜 카드 10개 (페이지의 주인공) — 필드별 기준
각 딜마다 **회사 발표 또는 투자 기사 + 1~2개 출처**를 더 찾는다. 수치는 2개 출처로 교차 확인. 확인 안 되면 `[미확인]`. 추측 금지.

| 필드 | 써야 할 것 | 분량 |
|---|---|---|
| `what` 어떤 회사인가 | 무엇을 만드는지(쉬운 말로, 비유 OK) · **고객이 누구인지(B2B/B2C, 주요 고객사)** · **돈 버는 방식** · 창업자 배경(왜 이 팀인지) · 제품/매출 유무 | 3~5문장 |
| `funding` 펀딩 내용 | 리드, 주요 참여사(VC·CVC·전략투자·정책금융 구분), 발표일, 브릿지/익스텐션 여부, 금액 출처 불일치 | 2~3문장 |
| `history` 펀딩 히스토리 | 직전 라운드 시점·금액·기업가치 → 상승 배수, 누적 투자액(THE VC 기준 명시) | 1~2문장 |
| `metrics` 핵심 지표 | 매출·영업이익·고객사·이용자 수·직원 수·특허·인증. "회사 주장"인지 표시 | 1~2문장 |
| `why` 왜 이 투자가 나왔나 — 시장의 방향 | **첫 문장은 `<b>한 줄 테제</b>`** (이 딜이 보여주는 국내 시장 흐름). 이어서 왜 지금 이 회사에 돈이 들어왔는지(트리거: 대기업 계약·해외 진출·인허가·정책), 어떤 큰 흐름의 일부인지(국내외 경쟁사·유사 딜), 리스크 1개 | 3~4문장 |
| `sources` | `[["매체명","URL"], ...]` 2~4개 | |

메타: `round`, `valuation`(기업가치. 비공개면 "비공개"), `lead`, `hq`("도시 · 설립연도"), `sector`(짧은 태그), **`amount_eok`(억원 숫자, 예: 350)**, `site`.

## 4. 페이지 섹션 — 각 섹션에서 볼 것
JSON 최상위에 **`"region": "kr"`** 필수. 원문 정보는 `source: {url, title, note}`.

| JSON 키 | 섹션 | 무엇을 쓸까 |
|---|---|---|
| `headline` | 헤드라인 | "A 350억원·B 300억원이 이끈 주간, 테마1·테마2… Top 10 합계 약 1,800억원" (마침표 없이) |
| `lead` | 리드 문단 | 그 주 전체 건수·공개 총액(스타트업레시피 기준), 상위 집중도(%), 두 번째 축 — 2문장 |
| `top_sector` / `top_sector_note` | 타일 | 예: "AI 4건" / "최다 섹터 (반도체 2건 포함)" |
| `trends` | 이번 주 시장의 방향 | 4개. 각 `<b>테제.</b>` + 근거 딜 1~2문장 |
| `others` | Top 10 밖 주목할 딜 | 3~5개 한 줄씩 (금액 비공개 대형 딜, 해외 VC의 국내 투자, 해외 법인 한국 창업 스타트업) |
| `news` | 플래텀 투자 뉴스 | 아래 '플래텀 투자 뉴스' 규칙 참고 |
| `sectors` | 1. 섹터별 동향 | **AI·딥테크 / 바이오·헬스케어 / 제조·로보틱스·모빌리티 / 핀테크·커머스·플랫폼 / 콘텐츠·기후·기타** 5개 고정. `stat`="금액 · 건수", `text`= 이번 주 딜 + Top 10 밖 딜 + 혁신의숲 월간 결산·중기부 통계로 맥락 3~5문장. 딜이 없으면 "이번 주 큰 딜 없음"과 최근 섹터 데이터 |
| `stages` | 2. 단계별 표 | 행 3개 고정: 시드·프리A / 시리즈 A / 시리즈 B 이후·프리IPO. `deals`는 `<br>`로 구분, `note`= 관찰 1~2문장 |
| `stage_note` | 단계 요약 | 메가딜(100억원+) 비중, 최신 월간 결산의 단계별 수치, 굵은 결론 1줄 |
| `exits` | 3. 상장 · M&A | 이번 주 상장예비심사 청구·승인, 수요예측·신규상장(VC 투자 기업), 스타트업 M&A. 없으면 "확인하지 못함" 명시 |
| `policy` | 3. 정책 · 모태펀드 | 2~4개. 모태펀드·정책펀드 출자, 대형 펀드 결성, 벤처 관련 정책·규제 변화. 없으면 "이번 주 큰 변화 없음" |
| `implications` | 4. 시사점 | 3개. `<b>결론.</b>` + 근거 |
| `watch` | 4. 다음 주 체크리스트 | 4개. 수요예측·상장 일정, 월간 결산 발표, 출자사업 결과, 진행 중인 대형 라운드 |
| `sources` | 5. 출처 | 15~25개. 스타트업레시피·혁신의숲·투자 기사 URL 우선 |
| `limits` | 데이터 한계 | 막힌 정보원, 추정 순위, 미확인 값, 회사 주장 수치, 금액 비공개 딜 제외 사실 |

텍스트 안 HTML은 `<b>`, `<br>`, `<a href>`만. 배지는 `[미확인]`, `[추정]` 문자열.

### 플래텀 투자 뉴스 (`news`)
- **START~END에 플래텀(platum.kr)에 올라온 투자 유치 기사를 빠짐없이** 모은다. Top 10과 겹쳐도 넣는다(Top 10은 금액 순 분석, 이 표는 그 주 뉴스 흐름).
- 찾는 법: ① `https://platum.kr/feed`(RSS)와 `https://platum.kr/archives/category/investment` 목록을 WebFetch로 연다(`/page/2` …). 플래텀은 클라우드 IP에 403을 주는 경우가 많다. ② 막히면 WebSearch `allowed_domains:["platum.kr"]` + "투자 유치" + 날짜. ③ 그래도 부족하면 **같은 주 투자 기사를 스타트업레시피·벤처스퀘어·유니콘팩토리 등 다른 매체에서 찾아 채운다**. 이 경우 각 항목 `summary` 끝에 출처 매체명을 괄호로 적고, `limits`에 "플래텀 대신 OO 기사로 보완"이라고 쓴다.
- 기사마다 본문을 열어 확인. 항목 형식: `{"date":"10-28","company":"회사명","amount":"50억원 · 시리즈 A" (비공개면 "비공개 · 시드"),"summary":"뭐하는 회사인지 1문장 + 리드 투자사·자금 용도 1문장","url":"기사 URL"}`. 날짜 오름차순.
- 펀드 결성·투자사 소식(투자 유치가 아닌 기사)은 넣지 않고 `policy`나 `others`로 보낸다.
- 대체 매체까지 써도 확인 가능한 기사가 0건일 때만 빈 배열로 두고 `limits`에 적는다. 본문을 못 읽은 기사는 넣지 않는다.

## 5. 문체
- 한국어 존댓말 평서문("~입니다"), 짧은 문장. 금액은 `350억원`, `1,200억원`, `1.2조원`. 필요하면 달러 환산을 괄호로(예: 약 $25M).
- 전문용어는 처음 나올 때 괄호로 풀이 (예: 브릿지 투자(다음 라운드 전 잇는 투자)).
- 과장·투자권유 금지. 회사 주장 수치는 "(회사 주장)".

## 6. 빌드 & 배포
```bash
git fetch origin && git checkout -B claude/pages origin/claude/pages
mkdir -p data/kr   # data/kr/START.json 작성
python3 tools/build_report.py data/kr/START.json   # 검증 실패 시 메시지대로 보완
git add -A && git commit -m "report(kr): START ~ END"
git pull --rebase origin claude/pages && git push origin claude/pages
```
- 빌더가 `kr/reports/START.html`, `kr/reports/index.json`, 루트 `index.html`(미국·국내 두 섹션)을 갱신한다. 미국판 파일은 건드리지 않는다. `.nojekyll` 유지.
- rebase 충돌이 `index.html`에서만 나면 빌더를 다시 실행해 재생성한 뒤 계속한다.
- PR 생성 금지. push 실패 시 에러를 그대로 보고.

## 7. 마무리

## 자체 점검 (push 전)
- [ ] `region: "kr"`, 금액 필드는 `amount_eok`
- [ ] 딜 10개 모두 `what` 3문장 이상, `why`가 `<b>테제</b>`로 시작
- [ ] 섹터 5개, 단계 3행, 시사점 3개, 체크리스트 4개, 정책 2개 이상
- [ ] 금액·기업가치·리드는 2출처 확인 또는 `[미확인]`
- [ ] 기준 목록의 대상 기간이 START~END와 일치
- [ ] 출처 15개 이상
- [ ] `news`에 대상 주 플래텀 투자 기사가 모두 들어 있음(날짜 범위 확인), 각 `summary` 2문장
